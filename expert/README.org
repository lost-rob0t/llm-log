#+title: llm-log expert runtime

* Boundary

This directory is the Common Lisp-owned expert-system runtime for llm-log.

- Tek9 is the durable document/graph KB.
- SWI-Prolog is the rule/inference engine.
- Common Lisp owns lifecycle, typed schemas, bounded fact materialization, Prolog supervision, result validation, and persistence.
- Python owns only proxy/capture transport plus the versioned client envelope in =llm_log/expert_protocol.py=.

The runtime is intentionally developed behind the black-box contract in =tests/test_expert_service_red.py=. Do not make the Python proxy a second rule engine and do not add an arbitrary Prolog goal operation.

* First executable contract

The first service must support:

#+begin_example
llm-log-expert serve --stdio --data-dir PATH
#+end_example

with one JSON object per input/output line. The implementation must keep one Tek9 database and one supervised SWI-Prolog session alive for the service lifetime.

Initial operations are named and closed: health, observations, and declared expert queries only. Untrusted strings are data, never executable Prolog terms.

* Mutable state

Runtime state belongs below the configured llm-log data root, conventionally:

#+begin_example
$XDG_DATA_HOME/llm-log/expert/
#+end_example

or below the Home Manager configured =services.llm-log.dataDir=. No mutable database state belongs in the Nix store.

* Packaging dependency

Tek9 currently exposes an ASDF system and development flake shell but no reusable Nix package output. The llm-log flake must consume Tek9 reproducibly before this runtime can be considered packaged/green; do not require a developer-local Quicklisp checkout.
