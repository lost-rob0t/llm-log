* Verified behavior
- finite declared =query_outcome_dataset= operation;
- result limit 1..64 with a hard internal candidate ceiling;
- exact outcome selection through the Tek9 =outcome-assertion-outcome= secondary index;
- deterministic bounded projection without per-request corpus scans;
- complete immutable assertion rule/version/expert provenance;
- evidence IDs plus point-fetched evidence/source provenance;
- missing evidence is an error, never silently dropped;
- superseded assertions excluded by default and available through explicit historical opt-in;
- truthful =truncated=true= when another matching current assertion exists;
- dataset export reads stored assertions and never re-runs SWI-Prolog, so historical labels cannot drift after rule changes;
- HTTP success remains unrelated to task-success inference;
- legacy durable outcome assertions survive expert-host restart and are made queryable through a versioned one-time index migration;
- migration marker is written only after successful index rebuild; crash before the marker safely repeats the idempotent rebuild;
- routine restarts and dataset requests do not rebuild/scan the corpus.

* Architecture result
Python remains capture/transport. Common Lisp owns typed query validation, bounded Tek9 materialization, index migration, and result projection. Tek9 remains the durable document/graph KB. SWI-Prolog remains the sole outcome inference owner.

No Tek9 repository production mutation and no dotfiles mutation were required. The existing Tek9 public =rebuild-index= and bounded index/query primitives were sufficient.
