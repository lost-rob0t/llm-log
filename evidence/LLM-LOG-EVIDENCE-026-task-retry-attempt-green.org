* Verified behavior
The retry fixture reconstructs explicit attempt/retry metadata after an expert-host restart while preserving the pre-existing accounting totals: three requests, 240 input tokens, 120 output tokens, and 0.48 USD known cost.

The bounded task query reports two persisted attempt IDs, one retry request ID, and incomplete metadata because the ordinary third request intentionally carries no attempt metadata. Missing attempt metadata remains explicit and does not suppress usage or cost.

Validation rejects non-positive attempt ordinals and self-referential retry predecessors. A conflicting replay for an immutable usage ID remains a conflict when actual evidence differs.

* Architecture evidence
The Common Lisp expert service extends immutable usage projections with optional explicit =attempt_id=, =attempt_ordinal=, =retry_of_request_id=, =client=, and =transport= evidence.

=query_task_accounting= derives counts and provenance only from the same bounded task subtree and =usage-task-id= Tek9 candidates already used by task accounting. It does not scan the corpus, infer retries from timing/session adjacency, reprice historical requests, or add a Python/Common Lisp rule engine. SWI-Prolog remains the owner of pricing inference.

No Tek9 repository mutation was required; existing durable document/index primitives remain sufficient.
