* Accepted product RED
The fixture durably created two independent tasks and one request usage per task. Both requests received authoritative =success= outcome assertions. The expert host was stopped and restarted before export.

The query requested:
- =outcome=success=;
- =task_cost_state=known=;
- =task_cost_currency=USD=;
- =task_cost_min_amount=0.30=.

The cheap task has immutable known cost USD 0.14. The expensive task has immutable known cost USD 0.40.

Untouched product returned *both* success examples. The contract's first new behavioral assertion expected exactly one example and observed two. Returned examples also had no =task_accounting= projection, causing the subsequent provenance assertions to fail.

This is the intended missing-product RED: current =query_outcome_dataset= ignores task-cost selectors. It is not a fixture syntax, dependency, startup, storage, or Prolog failure.
