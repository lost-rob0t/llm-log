#+title: LLM-LOG-RESEARCH-029 — Concrete expert adapter transport lifecycle
#+startup: overview

* Scope
Issue: https://github.com/lost-rob0t/llm-log/issues/10
PR: https://github.com/lost-rob0t/llm-log/pull/24

Bounded Auto-ARADR decision for exercising the concrete Python -> Common Lisp expert adapter through the real Python HTTP/WebSocket capture proxy. This document supersedes conflicting zero-Python issue prose for this boundary: Python remains transparent capture/transport; Common Lisp owns expert runtime, Tek9 and SWI-Prolog supervision.

* Analyze
Current =build_app= accepted an =expert_plane= and invoked =health()= before both ordinary HTTP and WebSocket forwarding. =SubprocessExpertPlane= already owned a long-lived JSON-lines child, but its =start()/close()= lifecycle was not connected to the aiohttp application lifecycle. Passing a fresh concrete adapter with =require_expert_plane=true= therefore could not become healthy without an external launcher starting it first.

* Research
The proxy already has one bounded startup/cleanup authority for its =ClientSession= and =RecorderActor=. The concrete subprocess adapter can be owned there without exposing Tek9, Prolog, or Common Lisp internals to Python. Startup failure must not kill the capture proxy because the default expert policy is fail-open; required mode remains fail-closed at the existing pre-forward health gate.

The same health gate is shared by HTTP and WebSocket forwarding, but dedicated WebSocket conformance is required rather than inferring parity from source placement.

* Design
** Typed boundary
- Python calls only declared adapter methods; no raw Prolog goal API.
- Concrete adapter remains one serialized long-lived Common Lisp subprocess.
- Common Lisp remains sole Tek9 client and Prolog supervisor.
- Tek9 remains the canonical durable expert KB.

** Lifecycle
- aiohttp startup starts an explicitly configured =SubprocessExpertPlane= after recorder/session setup;
- start failure is contained so default fail-open transport remains available;
- aiohttp cleanup closes the owned subprocess before recorder shutdown;
- no implicit restart or replay is introduced for ambiguous in-flight exchanges.

** Failure semantics
- expert start/health failure with default policy: proxy remains available and forwarding is fail-open;
- explicit =require_expert_plane=true=: request/upgrade returns 503 before upstream contact;
- ambiguous adapter exchange is never implicitly replayed;
- cleanup does not mutate raw capture evidence.

** Transport acceptance
The executable contract uses the concrete =SubprocessExpertPlane= and real aiohttp upstreams, proving:
1. app startup owns concrete adapter startup;
2. required healthy HTTP forwards;
3. existing default/required expert policy remains intact;
4. required healthy WebSocket upgrades and relays frames;
5. unavailable WebSocket fails open by default and fails closed when required;
6. app cleanup terminates the owned child;
7. isolated adapter no-replay and no-arbitrary-Prolog contracts remain GREEN.

* Adversarial review
Do not make structural fake =ExpertPlane= implementations acquire subprocess lifecycle authority. Do not restart a child on a failed in-flight exchange. Do not leak child stderr, credentials, protocol payloads, Tek9 records, or Prolog terms into proxy responses. Do not modify Tek9: no missing generic database primitive is implicated.

A startup exception is intentionally swallowed only for the concrete subprocess adapter. This preserves default fail-open behavior. =require_expert_plane=true= still fails closed at request time because =health()= observes that the adapter is unavailable before any upstream HTTP request or WebSocket upgrade.
