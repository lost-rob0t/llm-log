* Research
** Evidence boundary
Persisted raw evidence must preserve payload bytes exactly while never persisting credential-bearing header values. Persisting an unredacted raw HTTP header block is therefore forbidden even if it would be convenient for replay.

The capture representation separates:
- exact request body octets;
- exact response body octets;
- typed/redacted metadata and ordered headers;
- later derived Tek9 assertions.

This keeps raw capture distinct from symbolic derivations and avoids turning Tek9 into the raw traffic store.

** Header representation
Headers are ordered pairs, not a map. Duplicate fields are semantically significant and must remain representable. Redaction is case-insensitive.

Initial secret-name set:
- =Authorization=
- =Proxy-Authorization=
- =Cookie=
- =Set-Cookie=
- =X-Api-Key=
- =Api-Key=
- =OpenAI-Api-Key=
- =Anthropic-Api-Key=

Forwarding uses the original values. Persistence substitutes exactly =<redacted>=.

** Actor boundary
The final recorder is a single-writer actor. Sento/cl-gserver remains the preferred actor framework because it provides mailbox sequencing, ask/tell, actor lifecycle and supervision semantics. This bounded slice does not introduce the actor dependency yet: first freeze and execute the persistence/redaction contract on one request. A following RED must prove concurrent requests cannot interleave/corrupt evidence before the recorder actor is accepted.

* Design
For finite HTTP capture, each completed request creates one immutable event directory beneath:

#+begin_example
<data-directory>/capture/http/events/<event-id>/
  metadata.json
  request-body.bin
  response-body.bin
#+end_example

=event-id= is generated by the Common Lisp runtime and directory/file creation must reject an existing path rather than overwrite evidence.

=metadata.json= schema =llm-log.capture/http-v1= contains at minimum:
- event_id;
- provider selector;
- configured upstream;
- method;
- forwarded target (path + query);
- ordered request header pairs with persisted secret values redacted;
- response status;
- ordered response header pairs with persisted secret values redacted;
- transport =http=.

Bodies are stored as binary files, never JSON-round-tripped. Metadata is descriptive evidence, not an expert assertion.

The forwarding path must still send original credential values upstream. Redaction happens only on the persistence copy.

* Adversarial review
** Secret leakage through raw request persistence
Do not persist the raw request header block. Persist exact body bytes plus redacted typed headers.

** Secret leakage through response cookies
Treat =Set-Cookie= as sensitive in persistence while preserving every original =Set-Cookie= field toward the client.

** JSON map collapses duplicate headers
Use an ordered array of header pairs in metadata.

** Capture mutation changes traffic
Capture is observational. The same black-box request must still satisfy the existing raw HTTP fidelity test.

** File overwrite destroys immutability
Use create-only event paths/files. Collision is an explicit capture failure, never replacement.

** Concurrency creates corrupt evidence
Not claimed GREEN in this slice. Direct per-worker persistence is only acceptable as a bounded first semantic implementation if the contract is single-request. The next recorder slice must RED-test concurrent requests and replace direct persistence with one Sento/cl-gserver single-writer actor before capture migration is considered complete.

** Capture failure vs forwarding
Final policy remains fail-open for forwarding unless an explicit capture-required policy is introduced later. This slice must not persist credentials when capture fails.

* Decision
GO for one bounded RED-first Auto-RAGE slice: add and execute a Common Lisp black-box capture/redaction contract against the current ordinary-HTTP GREEN head. If the expected RED is observed, implement only enough finite-HTTP capture persistence to satisfy that unchanged contract, then require exact-head GREEN.

No Tek9 mutation is justified: this persistence is raw evidence, while Tek9 remains the canonical derived document/graph KB.

* RED-first acceptance
The new black-box contract sends an ordinary HTTP request containing unique credential sentinels in =Authorization=, =X-Api-Key= and =Cookie= plus a non-secret header. The fixture response includes two =Set-Cookie= fields and a non-secret response header.

The contract requires:
1. upstream receives the original credential values unchanged;
2. downstream still receives the original response semantics;
3. exactly one capture event directory exists;
4. request and response body files match exact binary octets including NUL;
5. metadata contains =<redacted>= for every secret header value;
6. no credential sentinel appears anywhere in persisted metadata;
7. non-secret request/response header values remain observable;
8. duplicate response header representation remains possible as ordered pairs;
9. existing ordinary HTTP fidelity tests remain GREEN.

This slice does not claim recorder concurrency, SSE, WebSocket, HTTPS, provider-family conformance, expert fail-open/fail-closed integration, or final zero-Python acceptance.
