This document is the canonical ARADR decision for the next bounded #12 slice. RESEARCH-036 remains authority for classifier semantics; RESEARCH-004/033 remain authority for the wider expert plane.

* Analyze
The first #12 slice persists provenance-bearing request-classification assertions, but #12 acceptance still requires explicit ambiguity plus bounded indexed retrieval by request/user-message/provider/model/time and restart/query conformance.

The database boundary does not justify a Tek9 change. Current Tek9 public APIs already expose durable DUPSORT secondary indexes, exact equality lookup, ordered secondary range lookup with a finite =limit=, direct bulk point reads, and graph adjacency APIs. A new generic Tek9 primitive is therefore not proven missing.

The executed RED at =2b95c54dd4a1436f06eccbc11e8b6d48cfb512da= failed for the intended reasons: =query_classification_history= was not a declared expert operation and the ambiguity fixture produced no =state=ambiguous= pair. Existing expert substrate behavior remained independently exercised.

* Research — typed local query contract
Add one declared expert operation, =query_classification_history=, owned by the Common Lisp expert service. It accepts only typed JSON-safe filters; callers cannot name Tek9 indexes, supply predicates, or pass executable Prolog terms.

Allowed bounded equality filters for the first GREEN slice:
- =request_id=
- =user_message_id=
- =provider=
- =model=
- =limit= with a hard service maximum of 64

At least one selective equality filter is required. Empty unbounded corpus scans are rejected with a typed =invalid_request= error. Time-range querying remains part of #12 acceptance but is deliberately not smuggled into this equality/restart slice without a timestamp-bearing RED fixture.

Returned records are durable derived assertion documents joined to their immutable classification-source projection. Each record retains assertion ID, event/user-message/request identity, dimension/value/state/confidence, rule ID/version, expert version, evidence IDs, provider/model/client metadata, publication revision and supersession metadata.

* Tek9 schema/index decision
Use existing Tek9 public secondary-index/range APIs from Common Lisp. The durable schema keeps source evidence and derived assertions distinct rather than duplicating every source field into every assertion.

Register process-local handles for durable indexes over classification-source documents:
- =classification-source-request-id=
- =classification-source-user-message-id=
- =classification-source-provider=
- =classification-source-model=
- reserved =classification-source-started-at= for the later time-range acceptance slice

Register one assertion provenance index:
- =classification-assertion-source-event=

Query planning stays bounded:
1. choose the strongest supplied equality source index in request/user-message/provider/model order;
2. use Tek9 =select-index-range= with identical start/end keys and an explicit candidate cap;
3. intersect remaining typed filters in Common Lisp only over that bounded source candidate set;
4. fetch each source event's derived assertions through the source-event assertion index with the remaining result limit;
5. retain only =request.classifier= assertions;
6. never use Tek9 full-scan =select= for this operation;
7. never materialize the classification corpus into Prolog.

This source-index + provenance-index join is preferred over duplicating provider/model/request fields into every derived assertion. It preserves the evidence/assertion separation while remaining bounded and restart-durable.

* Restart semantics
Classification source documents, derived assertions and LMDB secondary-index databases live in the canonical expert Tek9 data directory. Index definitions are process-local and are registered again when the Common Lisp host starts; durable index contents remain in Tek9. Closing and reopening the expert host against the same data directory must preserve query results.

Raw capture files remain separate immutable evidence. Restart tests operate on synthetic expert data and do not mutate capture fixtures outside their temporary test directory.

* Ambiguity contract
The classifier represents ambiguity explicitly in SWI-Prolog. A conditional review/fix request can emit competing same-dimension =operation= assertions, for example =review= and =fix=, both with =state=ambiguous= and their own declared rule IDs. Unknown remains distinct from ambiguous.

Common Lisp still validates the returned state, evidence IDs, versions and bounded assertion count before persistence. Ambiguity is analytical metadata only and grants no authority.

This slice does not add probabilistic ranking, model-generated labels, or a second Python/Common Lisp rule engine.

* Provenance / failure semantics
Every queried assertion links exact source evidence IDs and rule/version/expert version. Historical revisions are retained and superseded rather than deleted.

Unavailable or invalid history queries return a typed expert error. Python proxy forwarding remains fail-open unless =require_expert_plane= is explicitly true. Query failures never mutate or drop the original user request.

* Nix / non-Nix
No packaging boundary change is required. Existing SBCL + Tek9 + SWI-Prolog packaging and Home Manager/systemd service remain authoritative. Non-Nix launch/config paths are unchanged.

* Adversarial review
- Full corpus scan then Lisp filtering: reject; violates bounded indexed retrieval.
- Unbounded Tek9 equality helper that first materializes every duplicate posting: reject for the service path; use the range cursor with =limit=.
- Caller-provided index names or Lisp predicates: reject; expands execution surface.
- Query through Prolog over persisted corpus: reject; persistence/query belongs to CL + Tek9 and would load excess state into Prolog.
- Rebuild labels from raw traffic at query time: reject; conflates immutable evidence with derived assertions.
- Duplicate all source metadata into every assertion solely to simplify querying: reject for this slice; source/provenance indexes already provide a bounded join.
- Delete old conflicting assertions: reject; revisions must remain auditable.
- Treat ambiguous authority labels as permission: reject.
- Modify Tek9 before demonstrating an API gap: reject.

* Decision
Proceed with the bounded GREEN mutation on =rage/12-classifier-query-red= using only existing Tek9 APIs. Common Lisp owns index registration, typed query validation, bounded retrieval/join, result shaping and error handling. SWI-Prolog owns ambiguity rules. Python remains capture/transport and receives no rule engine.

The implementation must drive the already-executed RED contract GREEN while preserving the existing expert, Python policy/transport and Home Manager gates. No dotfiles pin/config change is justified until this llm-log slice is exact-head GREEN and merge-eligible.

Time-range querying remains explicitly open under #12 after this slice unless a timestamp RED contract and implementation are added before merge; do not silently claim full #12 acceptance without it.

* Exact RED/GREEN acceptance
1. Start expert host in a temporary data directory.
2. Classify at least two synthetic requests with different request IDs/provider/model metadata.
3. Stop and restart the host against the same directory.
4. Invoke declared =query_classification_history= with filters matching only one request/provider/model and a finite =limit=.
5. Require status =ok=, a bounded result list, no records from the other request, and preserved assertion/rule/source/expert provenance.
6. Require an empty/unbounded history query to fail with a typed bounded-query error rather than scanning the corpus.
7. Submit an ambiguity fixture and require at least two same-dimension =state=ambiguous= assertions; no assertion may grant authority.
8. Existing request-classifier compound fixture and expert roundtrip/failure contracts must remain unchanged.
9. Hosted CI must run on the exact current branch head; prior-head GREEN is evidence only, never a substitute.
