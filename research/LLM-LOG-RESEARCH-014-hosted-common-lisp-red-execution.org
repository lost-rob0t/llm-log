* Analyze
The active #10 branch has an authoritative Common Lisp/Rove transport contract and a Nix check named =common-lisp-transport-contract=. The automation container has no =sbcl=, =swipl=, =nix=, or =ros=, so local execution cannot establish behavioral RED.

A hosted GitHub runner was added only to supply an executable Nix environment. The first hosted execution exposed a second gate defect: the Rove assertions visibly execute, but the ASDF =test-op= ignored Rove's boolean result. Therefore failed Rove assertions could yield a successful Nix derivation.

This is a false-green harness bug. It does not authorize HTTP implementation.

* Research
GitHub-hosted Ubuntu runners can install Nix using =cachix/install-nix-action@v31=. The existing flake pins Tek9 and defines the exact Common Lisp transport check, so CI does not duplicate dependency assembly.

Canonical command:

#+begin_src sh
nix build -L .#checks.x86_64-linux.common-lisp-transport-contract
#+end_src

Rove's =run= ultimately returns two values from =call-with-suite=; the primary value is =(passedp *stats*)=. It does not signal an error merely because assertions failed. The previous ASDF performer called =rove:run= and discarded that boolean, so ASDF/Nix observed normal completion.

The test-system performer must convert false into a Common Lisp condition:

#+begin_src lisp
(unless (uiop:symbol-call :rove :run :llm-log-expert-test)
  (error "llm-log-expert-test failed"))
#+end_src

This keeps Rove as the test framework while making ASDF/Nix failure semantics truthful.

* Design
Hosted executor:

1. checkout exact commit;
2. install Nix;
3. execute only =checks.x86_64-linux.common-lisp-transport-contract=;
4. preserve GitHub Actions logs as execution evidence;
5. run on pushes to =rage/10-expert-runtime-red= and manual dispatch.

Do not run Python tests in this workflow.

The expected behavioral RED is a failed assertion for the absent Common Lisp proxy lifecycle surface: =START-HTTP-PROXY=, =STOP-HTTP-PROXY=, and =PROXY-LISTEN-PORT=. Bootstrap, flake-evaluation, dependency-load, ASDF-load, or Rove-load failures are infrastructure failures and do not authorize production implementation.

* Adversarial review
** False RED from dependency bootstrap
Treat bootstrap/evaluation/load failures as blockers, not behavioral evidence.

** False GREEN because the test framework returns a boolean
Resolved by making ASDF signal when Rove's primary return value is false. The exact hosted contract must be rerun after this correction.

** Workflow becomes a Python backdoor
The workflow executes only the Common Lisp Nix check. No Python runner is introduced.

** Hosted CI becomes canonical architecture
The flake/ASDF test remains canonical. GitHub Actions only supplies an executable environment.

** Secret leakage
No provider credentials, corpus paths, API keys, or captured traffic are supplied to the job.

** Accidental merge on expected failure
PR #18 remains draft. Expected RED is not merge evidence.

* Decision
GO. Keep the hosted executor and repair ASDF/Rove failure propagation. Do not mutate HTTP production code until the corrected exact-head run is genuinely RED for the missing lifecycle API.
