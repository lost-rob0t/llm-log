* Analyze
The active #10 branch has an authoritative Common Lisp/Rove transport contract and a Nix check named =common-lisp-transport-contract=. The automation container has no =sbcl=, =swipl=, =nix=, or =ros=, so local execution cannot establish behavioral RED.

A hosted GitHub runner was added only to supply an executable Nix environment. The first hosted execution exposed a second gate defect: Rove assertions executed, but the ASDF =test-op= ignored Rove's boolean result. Failed Rove assertions therefore yielded a successful Nix derivation.

That false-green harness defect is now corrected and a subsequent exact-head hosted run has independently confirmed the intended behavioral RED.

* Research
The existing flake pins Tek9 and defines the exact Common Lisp transport check, so CI does not duplicate SBCL/SWI/Tek9 dependency assembly.

Canonical command:

#+begin_src sh
nix build -L .#checks.x86_64-linux.common-lisp-transport-contract
#+end_src

Rove's =run= ultimately returns two values from =call-with-suite=; the primary value is =(passedp *stats*)=. It does not signal merely because assertions failed. The original ASDF performer discarded that boolean.

The corrected test-system performer converts false into a Common Lisp condition:

#+begin_src lisp
(unless (uiop:symbol-call :rove :run :llm-log-expert-test)
  (error "llm-log-expert-test failed"))
#+end_src

The hosted verifier then requires all three expected lifecycle assertion messages to be present before classifying the run as the required RED.

* Design
Hosted executor:

1. checkout exact commit;
2. install Nix;
3. execute only =checks.x86_64-linux.common-lisp-transport-contract=;
4. require the Nix contract itself to fail;
5. require explicit assertion evidence for =START-HTTP-PROXY=, =STOP-HTTP-PROXY=, and =PROXY-LISTEN-PORT=;
6. run on pushes to =rage/10-expert-runtime-red= and manual dispatch.

Do not run Python tests in this workflow.

Bootstrap, flake-evaluation, dependency-load, ASDF-load, or Rove-load failures are infrastructure failures and do not count as behavioral RED.

* Adversarial review
** False RED from dependency bootstrap
Resolved by matching the expected assertion evidence rather than accepting any non-zero command.

** False GREEN because the test framework returns a boolean
Resolved by making ASDF signal when Rove's primary return value is false.

** Workflow becomes a Python backdoor
The workflow executes only the Common Lisp Nix check. No Python runner is introduced.

** Hosted CI becomes canonical architecture
The flake/ASDF test remains canonical. GitHub Actions only supplies an executable environment.

** Secret leakage
No provider credentials, corpus paths, API keys, or captured traffic are supplied to the job.

** Weak RED accidentally authorizes fake HTTP stubs
The confirmed RED proves only the lifecycle surface is absent. It does not prove forwarding fidelity. Production transport work must not merely define stubs to satisfy these symbols. Before implementing real forwarding semantics, extend the Common Lisp contract with a black-box HTTP fixture covering method/path/query/body/status and duplicate-header preservation.

* Decision
GO for the #10 transport slice. The execution-infrastructure blocker is resolved and the Common Lisp lifecycle baseline is genuinely RED. The next production-capable step is a stronger black-box Common Lisp HTTP forwarding RED, followed by the minimum real implementation. Do not introduce lifecycle stubs solely to turn the current surface test green.
