#+title: SSE terminal integrity capture
#+filetags: :llm-log:solution:capture:streaming:

* Solves
[[id:16deebed-a87e-4070-913f-dc9015ad5ca7][Streaming captures need terminal integrity evidence]]

* Approach
Capture response integrity separately from the HTTP status. =status_kind= distinguishes normal upstream responses from connection failures and failures that occur after the downstream response is already prepared. A mid-stream upstream failure preserves the original status, headers, and relayed bytes, records =upstream_midstream_error=, and terminates the existing downstream stream instead of constructing a second HTTP response.

For =text/event-stream= responses, persist =stream_completed= only from protocol evidence. OpenAI-compatible =[DONE]= frames, provider finish/stop-reason fields, and known terminal SSE event types mark terminal completion. A clean transport EOF without terminal evidence records =stream_completed=false=. Non-SSE responses keep =stream_completed=null=. Provider finish reasons are retained in =finish_reason= without synthesizing missing values.
