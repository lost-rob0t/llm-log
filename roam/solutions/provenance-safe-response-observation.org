#+title: Provenance-safe response and usage observation
#+filetags: :llm-log:solution:expert:capture:

* Solves
[[id:llm-log-live-expert-response-observation][Live captures lacked response and usage expert observations]]

* Approach
After =RecorderActor.record= commits an immutable capture, schedule bounded expert observations from the same =CaptureEvent=. Project the request first, then independently attempt classification, response observation, and provider-reported usage observation. Every expert call is best-effort so a failed derived projection cannot block or corrupt forwarding.

The response payload includes the stable event/request ID, provider/model/transport, completion timestamp, response SHA-256, HTTP status, terminal status kind, latency, normalized stream state, and provider finish reason when present. It never includes the raw response body. The Common Lisp expert host persists this as immutable =response:<event-id>= state and verifies that its response hash and source metadata match the already-projected request event.

Usage is emitted only when the captured provider response contains authoritative token counters. Historical replay uses the same response and usage payload builders, keeping live and backfilled expert graphs aligned.
