#+title: Bounded supplied-schema validation for tool arguments
#+filetags: :llm-log:solution:model:anomaly:tools:schema:

* Solves
[[id:llm-log-tool-argument-schema-conformance-gap][Valid tool-call JSON lacked supplied schema conformance evidence]]

* Approach
Extend the observe-only tool-call detector after complete reconstruction and JSON decoding. Request parsing builds two bounded structures: the declared tool-name set and a matching name -> =parameters= schema map. A reconstructed call is schema-validated only when its name exactly matches the request declaration and its arguments already decoded successfully.

=llm_log.schema_validation= wraps the upstream =jsonschema= validator behind a deliberately narrow result type: =valid=, =violation=, or =unusable=. Before invoking the validator, schema traversal is bounded to 64 levels and 4096 nodes and rejects every =$ref= that does not begin with =#=. =validator_for= selects the declared JSON Schema dialect, =check_schema= rejects invalid request contracts, and local references are resolved by the validator's normal referencing implementation. Invalid or unresolvable schemas return =unusable= and cannot create model-blame evidence.

The first deterministic validation error is selected by instance path and validator keyword. The anomaly projection records only the validator keyword and an escaped JSON Pointer instance path, plus the existing tool-call index/name/argument-length metadata. It never copies =ValidationError.message=, the failing instance value, validator value, schema body, request prompt, or tool description.

=tool_arguments_schema_violation= uses detector version =tool-call-schema/1=, score 0.95, high severity, and the same model-behavior/quantization boundaries as the earlier detector family. Quantization remains =unknown= unless separately grounded and does not affect the schema score.

The implementation declares =jsonschema= and =referencing= directly in =pyproject.toml=, the Nix development/test Python closures, and =nix/package.nix=. This prevents CI-only dependency success and proves the delivered executable carries the same validator path.

* Boundary
This slice validates tool arguments only. It does not validate requested assistant response formats, infer task failure, detect repetition/length/encoding pathologies, or fetch remote schemas. Those remain separate bounded #58 detector slices.
